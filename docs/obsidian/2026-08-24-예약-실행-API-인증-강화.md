# 예약 실행 API 인증 강화

작성일: 2026-08-24

## 배경

예약 실행 API는 Supabase 관리자 권한으로 사용자 데이터를 읽고 메일 동기화나 푸시 발송을 수행한다. 기존에는 일부 경로가 요청자가 직접 만들 수 있는 Vercel 관련 헤더를 신뢰하거나, `CRON_SECRET`이 없을 때 인증을 생략했다.

## 변경

- 세 예약 실행 경로가 공통 인증 함수만 사용하도록 통일했다.
  - `/api/agent/tick`
  - `/api/purchase/mail/cron`
  - `/api/push/dispatch`
- `Authorization: Bearer CRON_SECRET` 또는 `x-cron-secret: CRON_SECRET`만 허용한다.
- `CRON_SECRET`이 설정되지 않으면 401로 거부하는 fail-closed 정책을 적용했다.
- Vercel 스케줄 헤더와 User-Agent만으로는 인증되지 않는 회귀 테스트를 추가했다.

## 운영 확인

Vercel과 GitHub Actions에 같은 `CRON_SECRET`이 설정되어 있어야 한다. 이번 작업에서는 운영 환경변수 변경, 실제 예약 호출, 푸시 발송, 메일 동기화를 수행하지 않았다.

## 2026-08-24 감독 검증

### 비밀값 설정 여부

- 연결된 Vercel 프로젝트 `my-secretary-remote`: `CRON_SECRET` 있음, `production` 대상
- GitHub 저장소 `savioson2022-byte/my-secretary` Actions secrets: `CRON_SECRET` 없음
- 양쪽 모두 비밀값 자체는 조회·출력하지 않고 이름의 존재 여부만 확인했다.
- 비밀값 생성·변경·회전·삭제는 수행하지 않았다.

### 구매 자동화 검증 수정

- `getDueRepurchaseHistories()`가 검증 스크립트의 세 번째 `now` 인자를 받지 않아, 2026-07-14를 기준으로 한 미래 항목을 실제 시각인 2026-08-24에 기한 도래로 판정했다.
- 하위 함수 `isRepurchaseDue(history, now)`는 이미 기준 시각 주입을 지원하므로, 상위 함수가 `now`를 받아 그대로 전달하도록 수정했다.
- `909c1e7c (Improve Coupang mail purchase extraction)`에서 수량을 `productName`에서 제거하고 `quantityText`로 분리하도록 구현이 변경됐지만 이전 테스트 기대값은 그대로였다. 구현 계약에 맞게 기대 상품명을 `탐사수 생수 2L`로 수정했고 `quantityText`의 `12개` 검증은 유지했다.
