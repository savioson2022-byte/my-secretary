- 확인일: 2026-08-14
- 작업 유형: 읽기 전용 연결 대상 조사
- 환경변수 변경: 수행하지 않음

## 결론

현재 실제 운영 중인 나의 비서는 `my-secretary` 조직의 프로젝트를 사용한다.

| 구분 | 조직 | 프로젝트 이름 | 프로젝트 참조값 | 리전 | 상태 |
|---|---|---|---|---|---|
| 현재 나의 비서 운영 DB | `my-secretary` | `savioson2022-byte's Project` | `fesrtvxmqalkispmmhro` | `ap-southeast-1` | `ACTIVE_HEALTHY` |
| 이전 나의 비서 후보 | `savioson2022-byte's Org` | `savioson2022-byte's Project` | `dqcmcgxaubztejdnsggv` | `ap-northeast-1` | `INACTIVE` |
| 매쓰플랫 | `savioson2022-byte's Org` | `mathflat-classroom-assistant` | `bbdtjpfqpqiixvfendtx` | `ap-northeast-2` | `ACTIVE_HEALTHY` |

프로젝트 표시 이름이 같아 혼동하기 쉽지만 프로젝트 참조값과 소속 조직이 완전히 다르다.

## 확인 근거

1. 로컬 `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`이 `https://fesrtvxmqalkispmmhro.supabase.co`를 가리킨다.
2. 운영 Vercel 사이트가 배포한 공개 JavaScript에도 같은 Supabase URL만 포함되어 있다.
3. 코드와 설정 전체에서 이전 프로젝트 참조값 `dqcmcgxaubztejdnsggv`는 발견되지 않았다.
4. 운영 프로젝트 `fesrtvxmqalkispmmhro`에는 2026-08-14 현재 알림 스케줄러가 매분 `notification_events`, `notification_schedule_entries`를 조회하는 정상 API 활동이 있다.
5. 이전 프로젝트 후보 `dqcmcgxaubztejdnsggv`는 일시 중지된 `INACTIVE` 상태이며 최근 24시간 API 로그가 없다.
6. 생성 시각도 `dqcmcgxaubztejdnsggv`가 `fesrtvxmqalkispmmhro`보다 먼저다.

## 삭제 전 권장 절차

현재 증거만 보면 `dqcmcgxaubztejdnsggv`는 현재 나의 비서 앱에서 사용하지 않는 이전 프로젝트일 가능성이 매우 높다. 다만 삭제는 복구가 어려우므로 다음을 먼저 수행한다.

1. 이전 프로젝트의 데이터베이스·Storage·Auth 사용자 백업 여부 확인
2. 프로젝트 URL이 다른 저장소, Vercel 프로젝트, 자동화 또는 외부 서비스에 남아 있지 않은지 최종 검색
3. 필요 데이터가 없으면 `dqcmcgxaubztejdnsggv`만 정확히 삭제
4. `savioson2022-byte's Org`에 새 프로젝트 생성
5. 새 프로젝트의 목적과 이름을 기존 프로젝트와 구별되게 지정

현재 운영 프로젝트 `fesrtvxmqalkispmmhro`는 삭제하거나 연결을 변경하면 로그인, 사용자 데이터, 일정, 알림이 모두 중단될 수 있으므로 건드리면 안 된다.

## 삭제 전 데이터 확인 진행 상황

- `mathflat-classroom-assistant`(`bbdtjpfqpqiixvfendtx`)는 보호 대상으로 지정했으며 변경하지 않았다.
- 이전 프로젝트 `dqcmcgxaubztejdnsggv`에는 Edge Function이 없다.
- 이전 프로젝트는 중지 상태라 DB 테이블과 마이그레이션 조회가 연결 시간 초과로 실패했다.
- 프로젝트 복원을 요청했으나 계정의 활성 Free 프로젝트 2개 한도 때문에 Supabase가 거부했다.
- 매쓰플랫 또는 현재 운영 프로젝트를 임의로 중지하는 우회는 실행하지 않았다.
- Supabase 공식 문서상 프로젝트 삭제 시 DB, Auth 사용자, Storage, 백업, 키가 모두 영구 삭제되며 복구할 수 없다.

내부 데이터를 직접 확인하려면 다음 중 하나가 필요하다.

1. 현재 운영 나의 비서를 잠시 중지한 뒤 이전 프로젝트를 복원·백업하고, 이전 프로젝트를 다시 중지한 뒤 운영 프로젝트를 복원한다. 이 방식은 운영 중단 위험이 있다.
2. Supabase 활성 프로젝트 한도를 늘릴 수 있는 유료 플랜을 사용해 이전 프로젝트를 복원한다.
3. 내부 데이터 확인 없이, 현재 앱에서 사용하지 않는다는 외부 연결 증거만으로 이전 프로젝트를 바로 삭제한다. 이 방식은 이전 데이터 복구가 불가능하다.
