# 1e 실기기 검증 체크리스트

목적: `CalendarBridgePlugin`의 판정 규칙 6개가 실제 캘린더 데이터에서 의도대로 동작하는지 확인한다.
소요: 준비 5분 + 확인 10분.

## 먼저 알아야 할 것

`capacitor.config.ts`의 `server.url`이 `https://my-secretary-remote.vercel.app`로 되어 있다.
**네이티브 앱은 번들된 웹 자산이 아니라 이 원격 주소를 띄운다.**

따라서 검증하려면 두 가지가 모두 필요하다.

1. **네이티브 빌드** — 플러그인은 Swift이므로 Xcode에서 새로 설치해야 한다.
2. **웹 배포** — 설정 화면과 빈 시간 계산은 JS이므로 원격 주소에 올라가 있어야 한다.

Safari나 홈 화면 PWA로는 검증할 수 없다. 그쪽에는 `CalendarBridge` 플러그인이 없어서
항상 "캘린더 연동은 현재 iPhone 앱에서만 지원합니다"가 표시된다.

### 빠른 경로 (배포 없이)

`capacitor.config.ts`의 `server.url`을 Mac의 LAN 주소로 잠시 바꾼다.

```ts
url: "http://172.30.1.84:3001",
cleartext: true,
```

그리고 `npm run dev -- -H 0.0.0.0 -p 3001`로 개발 서버를 띄운다.
검증이 끝나면 **원래 주소로 되돌린다.** 되돌리지 않고 배포하면 앱이 빈 화면이 된다.

### 일반 경로 (배포)

```bash
git add -A && git commit -m "feat: read system calendar for accurate free time"
git push
```

Vercel 배포가 끝난 뒤 아래 준비를 진행한다.

## 준비

```bash
npm run ios:sync
npm run ios:open
```

Xcode에서 실기기를 선택하고 실행한다. 플러그인이 추가됐으므로 시뮬레이터가 아니라
**실제 iPhone**이어야 한다. 시뮬레이터에는 캘린더 데이터가 없다.

## 확인 순서

### 0. 권한이 먼저 뜨지 않는지

앱을 열자마자 캘린더 권한을 묻지 **않아야** 한다.
`설정 → 캘린더 연동 → 캘린더 연동 켜기`를 눌렀을 때만 물어야 한다.

- [ ] 앱 첫 진입에서 캘린더 권한 팝업이 뜨지 않는다
- [ ] 연동 켜기를 눌렀을 때 iOS 권한 팝업이 뜬다
- [ ] 허용하면 상태가 `연결됨`으로 바뀌고 캘린더 목록이 나온다

### 1. 캘린더 목록 (규칙 5)

- [ ] iCloud, Gmail 등 실제 계정 이름이 보인다
- [ ] **생일 캘린더는 목록에 아예 없다**
- [ ] 공휴일 같은 구독 캘린더는 보이되 **체크가 꺼져 있다**
- [ ] 내 개인 캘린더는 체크가 켜져 있다

### 2. 읽어온 일정 확인 — 여기가 핵심 관측 지점

`설정 → 캘린더 연동` 화면 아래쪽 **읽어온 일정 확인** 카드를 쓴다.
빈 시간을 눈대중으로 비교할 필요 없이, 플러그인이 실제로 무엇을 읽었고 각 일정에
어떤 판정이 적용됐는지 그대로 보여준다.

이 카드가 보여주는 것:

- **연동 전 / 연동 후 / 줄어든 시간** — 세 숫자. 연동이 실제로 계산에 반영되면 가운데가 작아진다.
- 읽어온 일정 목록, 각각에 `시간 점유` 또는 `제외됨` 배지
- 제외된 일정에는 **제외 사유**가 그대로 표시된다 (`거절한 회의`, `한가함으로 표시`, `종일 일정`, `취소된 일정`)
- 앱이 만든 일정에는 `이 앱이 만든 일정 (중복 계산하지 않음)` 표시
- 날짜를 바꿔가며 아무 날이나 확인할 수 있다

확인:

- [ ] 오늘 날짜에서 `연동 후` 빈 시간이 `연동 전`보다 작다 (오늘 캘린더에 일정이 있다면)
- [ ] 읽어온 일정 개수가 iOS 캘린더 앱에서 보이는 것과 같다
- [ ] `캘린더 → 주간` 화면의 빈 시간도 같은 값으로 줄어 있다

### 3. 판정 규칙 (완료 기준 2)

각 항목을 iOS 캘린더 앱에서 만들고, **읽어온 일정 확인** 카드에서 그 일정을 찾아
배지와 제외 사유를 확인한다. 빈 시간 숫자가 아니라 **배지를 본다.**

| 만들 일정 | 기대 배지 | 기대 제외 사유 |
| --- | --- | --- |
| 종일 일정 (예: "휴가") | `제외됨` | 종일 일정 |
| "한가함"으로 표시한 일정 | `제외됨` | 한가함으로 표시 |
| 초대받고 **거절**한 회의 | `제외됨` | 거절한 회의 |
| 초대받고 아직 응답 안 한 회의 | `시간 점유` | — |
| 보통의 일정 | `시간 점유` | — |

자정 넘김(규칙 4)은 목록에서 시간으로 확인한다.

| 만들 일정 | 기대 결과 |
| --- | --- |
| 22:00~다음날 02:00 | 오늘 날짜에 `22:00 – 24:00`, 내일 날짜에 `00:00 – 02:00`으로 **두 줄**로 나온다 |

공휴일(규칙 5)은 목록에 **아예 안 나와야** 한다. 구독 캘린더가 꺼져 있으므로 조회 대상이 아니다.

- [ ] 위가 모두 기대대로다

### 4. 캘린더 변경 반영

- [ ] iOS 캘린더 앱에서 일정을 추가하고 앱으로 돌아오면 빈 시간이 자동으로 갱신된다

### 5. 껐을 때 원래대로

- [ ] `연동 끄기`를 누르면 빈 시간이 연동 전 상태로 돌아간다
- [ ] 앱이 오류 없이 동작한다

## 실패했을 때 볼 곳

| 증상 | 볼 파일 |
| --- | --- |
| 목록이 비어 있음 | `CalendarBridgePlugin.swift`의 `listCalendars`, 권한 상태 |
| 배지나 제외 사유가 틀림 | `CalendarBridgePlugin.swift`의 `findExclusionReason` |
| 밤 일정이 안 잡힘 | `serialize()`의 자정 분할, `"24:00"` 반환 |
| 연동은 됐는데 빈 시간이 그대로 | `useExternalCalendarEvents.ts`, 캘린더 체크 상태 |
| "앱을 업데이트하세요"가 뜸 | 플러그인 등록 (`MySecretaryBridgeViewController.swift`) |

**읽어온 일정 확인** 카드가 대부분의 질문에 답한다. 목록이 아예 비어 있을 때만
Xcode 콘솔에서 권한 관련 오류를 확인하면 된다.
