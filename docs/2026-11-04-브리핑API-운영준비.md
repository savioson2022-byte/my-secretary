# 요청
옵시디언 `11_BriefingAPI.md`에 정의된 읽기 전용 API를 검증하고 Vercel 운영 설정·배포를 수행한다.

# 검증 및 보완
- 기존 순수 로직 검사 21개 통과.
- 프로덕션 빌드 성공.
- 로컬 HTTP 검사 11개 통과: 인증 없음/불일치 401, 쿼리 토큰/잘못된 범위 400, DB 미설정 503, POST/PUT/PATCH/DELETE/HEAD/OPTIONS 405, no-store 및 Allow 확인.
- 계정 연결 조회 실패를 무시하지 않고 전체 요청을 오류로 처리하도록 보완.
- HEAD/OPTIONS도 명시적으로 차단해 GET 전용 계약을 맞춤.
- 토큰 값과 개인 일정 내용은 문서·로그에 기록하지 않음.

# 운영 설정
- 프로젝트: my-secretary-remote
- 기존 SUPABASE_SERVICE_ROLE_KEY 등록 확인. 값은 조회하거나 출력하지 않음.
- BRIEFING_LOGIN_ID: newchoee
- BRIEFING_API_TOKEN: 운영 전용으로 새로 생성 필요. 생성·키체인 보관 승인 요청 중.
- Supabase MCP로 해당 프로젝트를 조회할 권한이 없어 실제 계정 조회는 운영 API 검증으로 확인 예정.
- Vercel 2FA 권장 안내는 사용자의 명시적 승인으로 닫았으며 인증 설정을 변경하지 않음.

# 연동 범위
API 설정 및 배포와 별개로 외부 브리핑 봇이 같은 토큰을 사용하도록 연결해야 한다. 봇 위치·비밀 저장소가 이 문서에 없어 임의로 외부에 토큰을 전달하거나 Slack 메시지를 보내지 않았다.

## 사용자 승인 후 운영 설정
- BRIEFING_LOGIN_ID=newchoee를 Production에 등록했다.
- 브리핑 전용 토큰 생성 및 Vercel Secret·Mac 키체인 보관을 사용자에게 명시적으로 승인받았다.
- 키체인 service: `app.mysecretary.briefing-api`, account: `newchoee`.
- 임시 토큰이 설정 도구의 화면 관측 출력에 포함되어 폐기하고, 최종 토큰으로 교체했다. 최종 값은 출력하지 않았다.
- 브라우저 전달은 일회용 RSA 암호화로 진행하고 임시 공개키·암호문은 정리했다. 평문 토큰 파일 없음.
- 운영 검증 스크립트: `node scripts/check-briefing-api.mjs`. 키체인을 읽어 인증 호출하되 개인 데이터와 토큰은 출력하지 않고 건수·검사 결과만 표시한다.
- 새 환경변수가 포함되도록 최신 API 소스 재배포를 진행한다.


## 최종 재인증 대기
- 코드 배포 a78bada는 Ready이나, 최종 토큰 교체 후 재배포는 Vercel의 이메일 재인증 단계에서 대기 중이다.
- 대상 이메일로 인증코드를 요청했고, Chrome 재인증 창을 사용자 인계 상태로 열어뒀다.
- 현재 운영 검증은 새 토큰으로 401이므로 완료로 판단하면 안 된다. 재인증 후 최신 a78bada 소스로 재배포하고 `node scripts/check-briefing-api.mjs`를 실행해야 한다.
- 최종 토큰과 키체인 값이 일치하도록 Vercel의 Edit → Save로 갱신 성공을 확인했다.
- 기존 배포는 환경변수 변경만으로 바뀌지 않으므로 초기 토큰의 운영 무효화도 최종 재배포 이후 확인해야 한다.

## 인증 후 계정 조회 보완
- 이메일 재인증 후 최종 토큰 포함 재배포를 완료했다. 인증은 통과했으나 대상 계정 조회가 503이었다.
- Supabase Dashboard의 승인된 기존 GitHub 로그인으로 구조와 대상 계정 연결을 읽기 전용 조회했다.
- newchoee 계정에 app_login_credentials 연결이 없고, 동일 실제 사용자에 app_accounts 행이 중복 생성돼 있었다. 표시이름으로 권한을 판별하지 않는다.
- 검증된 실제 사용자 UUID를 Production의 BRIEFING_USER_ID로 고정했다. 이 모드에서는 admin.getUserById로 존재를 확인한 후 해당 사용자 한 명만 조회하며 다른 계정으로 확장하지 않는다.
- 대상 동기화 데이터 건수는 단기 일정 0, 정기 일정 22, 기록 0이었다. 내용은 출력하지 않았다.
- 중복 계정 행 정리나 기존 로그인·동기화 로직 변경은 이번 읽기 API 작업에 포함하지 않았다.
- 해당 보완의 로컬 빌드·타입 검사·순수 로직 21개 검사 통과.
