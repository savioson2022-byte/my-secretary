# 나의 비서 미완성·후속 작업 점검

점검일: 2026-08-01

## 앱 심사 전 확인 필요

1. **Apple 로그인 실기기 검증**
   - 네이티브 구현, App ID 권한, Supabase 제공자 설정과 Release 컴파일은 완료됨.
   - 실제 iPhone에서 최초 로그인, 이메일 가리기, 재로그인, 로그아웃 후 재로그인을 확인해야 함.
2. **외부 AI 동의 흐름 실기기 검증**
   - 최초 동의/거부, 설정에서 철회, 철회 후 규칙 기반 분류, 재동의 후 OpenAI 분류를 확인해야 함.
3. **심사용 새 빌드와 메타데이터**
   - 변경된 아이콘·Apple 로그인·개인정보 동의가 포함된 새 빌드를 업로드하고 심사 답변 및 스크린샷을 갱신해야 함.
4. **캘린더 읽기 권한 심사** (2026-08-19 추가)
   - 1단계 외부 캘린더 연동으로 `NSCalendarsFullAccessUsageDescription`과 `NSCalendarsUsageDescription`이 추가됨. 새 권한이므로 심사를 다시 받기로 결정함.
   - 심사 답변에 "이미 일정이 잡힌 시간을 제외하고 빈 시간을 계산하기 위해 읽기만 사용하며, 앱이 만든 일정은 전용 `나의 비서` 캘린더에만 쓴다"를 포함해야 함.
   - 설계는 `docs/calendar-integration-plan.md` 참고.

## 사용자에게 보이지만 아직 완성되지 않은 부분

1. **통합계정 수동 연결**
   - 계정 화면에 연결 상태 모델은 있으나, 이미 별도로 만든 Apple/이메일 계정을 사용자가 직접 합치는 UI는 아직 없음.
   - 현재 문구에 `통합계정 연결 준비 중`이 노출됨.
2. **지원 문의 채널**
   - 지원 페이지에 문의 채널이 준비 중이라고 표시됨. 계정 삭제는 앱 안에서 가능하지만 일반 문의 접수 수단이 없음.
3. **웹에서 Apple 로그인**
   - 현재 구현은 iOS 네이티브 전용임. 웹 OAuth는 의도적으로 지원하지 않으며, 추후 지원 시 Apple Services ID와 6개월 주기 secret 갱신 운영이 필요함.

## 플랫폼 제약 또는 운영 설정 의존

1. **백그라운드 위치 기반 출발 알림**
   - 브라우저/PWA가 종료된 상태에서는 30분 간격의 지속 위치 확인을 보장할 수 없음. 완전한 백그라운드 추적은 iOS 네이티브 위치 권한·백그라운드 모드 설계가 별도로 필요함.
2. **사용자가 확인할 때까지 울리는 강한 알람**
   - 웹/PWA는 OS의 소리·집중 모드·백그라운드 제한을 우회할 수 없음. 앱 내부 지속 알람은 앱이 실행 중일 때 가장 확실하며, iOS의 Critical Alerts는 별도 Apple entitlement 승인이 필요함.
3. **메일·지도·푸시 제공자**
   - Gmail/Naver 자동 수집, Kakao/ODsay 이동시간, APNs/Web Push는 운영 환경변수와 각 제공자 콘솔 상태에 의존함.
4. **Gemma 개인화**
   - 모델 재학습이 아니라 승인·수정 기록을 컨텍스트 메모리로 반영하는 방식임. 모델 설치와 추론은 iPhone 앱에서만 지원됨.

## 품질 후속 작업

1. React Hook 의존성 관련 기존 lint 경고 10개 정리.
2. 토큰 암호화 외 핵심 흐름의 자동 테스트 부족: 로그인, 동의, 분류 승인/저장, 자정 넘김 일정, 장소 수정 저장, 푸시 확인을 E2E로 추가.
3. 개인정보 동의 및 AI API 거부(401/403), 철회 후 cron 제외 동작에 대한 서버 통합 테스트 추가.
4. App Store 심사 후 Sentry 같은 운영 오류 수집 도구 도입 검토.
